# 以大模型为研究对象、以心血管为背景的候选研究问题（2026-09-23）

**依据：** HTN-Concord 文献地图（80 篇）、方向 ①②③ 的三轮新颖性检索（约 40 篇），加上本轮针对「大模型本身」的补充检索（知识冲突、可验证奖励强化学习、推理算力、选择性作答）。
**资源约束：** Colab GPU；本地用 Hugging Face / Qwen；高级模型用 OpenAI API。
**硬约束：** 每个问题的标准答案都必须能由程序算出，不需要医生裁定。

---

## 0. 先看已发表的心血管 / 高血压 LLM 研究在做什么

把已发表工作按「研究对象」分类，就能看出空位在哪：

| 已发表研究的主流做法 | 例子 | 落点 |
|---|---|---|
| 拿现成模型答题，和医生比分数 | AHA 高血压 51 例（GPT-4 83%）；Sci Rep 医院分层对比；房颤抗凝 9 模型 | **医学**：模型能不能用 |
| 换提示词提分 | npj 高血压提示工程（62.7% → 91.3%）；心脏团队模拟 | **医学**：怎么用得更好 |
| 搭一个系统（RAG / agent） | 高血压 Cascade agent；心血管营养 RAG；心内膜炎 RAG | **应用**：造工具 |
| 抽取 + 确定性计算 | EHJ-DH 风险管线（α 0.78 vs 0.32）；SCORE2 vignette（重算后 κw 0.69 → 0.85–0.90） | **半方法**：已经发现「LLM 会读不会算」 |

**共同的问题：** 这些研究几乎都停在「这个模型在这个任务上多少分」。它们没有回答**为什么**，没有把失败归到大模型的某种机制（知识冲突、计算、校准、算力分配），也没有用心血管数据去**训练或改造模型**。另外，真值普遍依赖医生评分或 LLM 评委，所以结论难以复现。

**我们的切入点：** 心血管风险决策有一个其他医学任务少见的特点：**核心逻辑是已发表的方程和阈值**（PREVENT、PCE、SCORE2）。这让它成为研究大模型本身的理想**试验台**：标准答案可以由程序无限生成、精确计算，而研究的问题是大模型领域的通用问题。

## 1. 五个候选研究问题

### RQ-A 指南更新时，模型听上下文还是听记忆？（知识冲突）

**具体情境：** 2017 年版美国高血压指南用 PCE 方程，风险 ≥10% 就开药；2025 年版换成 PREVENT 方程，阈值改为 ≥7.5%。PCE 大约把风险高估一倍，所以**同一个病人按两个版本可能得到相反的结论**。大多数模型在训练中大量见过 2017 版。在提示里明确告诉模型「用 2025 版」，它会照做，还是会不自觉地退回 PCE 和 10%？

**研究问题：**
1. 在两个版本结论不同的病例上，模型的决定与哪个版本一致？有多少比例「退回旧版」？
2. 新规则以什么方式给出时，模型最听话：一句指令、整段指南原文、RAG 检索片段，还是给一个计算工具？
3. 退回旧版的程度与模型规模、训练截止时间、上下文长度有什么关系？
4. 能否用 LoRA 微调或知识编辑，在开源 Qwen 上把旧知识「改过来」，同时不破坏其他能力？

**研究价值：** 上下文与参数知识的冲突是大模型的核心问题之一；医学指南更新频繁，这是它最真实的一种落地形式。已有的医学工作是 **TempoMed-Bench**（选择题、考察回忆）、**DriftMedQA**（人工构造的「伪过时」推荐），以及 **MedCounterFact**（发现模型几乎无条件接受上下文里的假证据）。它们都没有**病人层面、结论可计算、新旧两版都真实存在**的冲突测试。我们能精确地知道每个病例上「照新版」和「照旧版」分别该答什么。

**怎么回答：**
- **数据：** NHANES 4,806 人，公开数据，可以直接发给 API。用 PREVENT 和 PCE 都算一遍，筛出两版结论不同的病例作为「冲突集」，结论相同的作为「对照集」。
- **标准答案：** 两个方程，全部由程序算出。PCE 需要按 Goff 2013 原文录入系数，再用原文算例验证，和当初做 PREVENT 的流程一样。
- **模型：** Qwen3 0.6B–32B（本地或 Colab），GPT 系列（API）。
- **实验条件：** 只给指令 / 给原文 / RAG / 给工具 × 冲突集 / 对照集。
- **指标：** 退回旧版率 = 冲突集上与 PCE@10% 一致的比例；对照集准确率作为基线。
- **进阶：** 在 Qwen 上做 LoRA 知识更新，测更新后的退回旧版率，以及在无关任务上的退化（MedQA 等）。可选加一层探针：模型内部读出的是 PREVENT 值还是 PCE 值，这就把原来的方向 ③ 并进来了。

**风险：**
- 前沿模型可能完全照上下文执行，得到零结果。**应对：** 把规模曲线作为主要结果；增加「只给原文、不直说阈值」的隐式条件，这时模型必须自己从原文里找到规则。
- PCE 的系数录入需要按原文核对（不需要临床判断）。

### RQ-B 信息不全时，模型知道自己「能不能下结论」吗？（选择性作答 / 可判定性）

**具体情境：** 就是方向 ② 修改后的版本。缺了胆固醇，有的病人风险无论如何都 >7.5%（应该作答），有的病人会落在阈值两侧（应该弃权）。

**研究问题：**
1. LLM 区分「可判定」和「不可判定」的能力如何？两类错误（过早下结论、过度弃权）各占多少？
2. 哪种不确定性信号最能预测「该弃权」：模型自报的置信度、多次采样的一致性、token 概率，还是隐藏状态探针？
3. 神经-符号架构（LLM 只负责抽取和识别缺失，由区间求解器判断是否可判定）比端到端 LLM 好多少？代价是什么？
4. 用「可判定性」作为奖励来训练小模型，能否学会恰当弃权？

**研究价值：** 选择性预测（何时不答）是大模型可靠性研究的核心问题，但一直缺**有精确标准答案**的测试台。多数「该不该弃权」的标注靠人判断，或者靠删除选择题的正确选项来人造。我们的可判定性由区间运算**数学上确定**。唯一的前作 ClinDet-Bench 只有 94 个人造病例、计分式量表。

**怎么回答：**
- **数据：** NHANES（公开，可用 API）；MIMIC 真实病历（**只能本地跑 Qwen**，见 §3 数据约束）。可行性已经实测：隐去血脂后，τ = 7.5% 时 61.8% 可判定、38.2% 不可判定。
- **标准答案：** 区间运算（`03_determinability.py` 已经写好）。
- **条件：** 端到端 / 神经-符号 / 给工具；阈值 τ 在 5–20% 之间扫描；缺失的变量组合（缺血脂、缺糖尿病状态、同时缺多项）。
- **指标：** 风险-覆盖率曲线、两类错误率、各种不确定性信号的 AUROC。

**风险：**
- 与 SCORE2、EHJ-DH 那两篇相邻，必须明确「我们测的是弃权，不是计算」。
- 住院人群风险偏高，「一定低于阈值」的病例少，需要分层抽样或引入 NHANES。

### RQ-C 小模型能否只靠「程序给分」的强化学习学会临床计算？学到的是能力还是格式？（可验证奖励 RL）

**具体情境：** 用 Qwen2.5 / Qwen3 1.5B–7B，按 GRPO（DeepSeek-R1 那一类训练方法）训练，奖励完全由程序给出：风险算对了没有、决策对不对、该弃权时有没有弃权。不用任何 LLM 评委，也不用人工标注。

**研究问题：**
1. 一个几 B 参数的本地模型，经过可验证奖励训练，在这类任务上能否接近 GPT 级别的 API 模型？
2. **泛化：** 在模板化病例上训练，能否迁移到真实 MIMIC 病历？在 PREVENT 上训练，能否迁移到没见过的方程（PCE、SCORE2）？
3. 强化学习带来的提升，是真正学会了计算，还是只学会了输出格式、减少了失误？近期有「RLVR 让模型更快，而不是更聪明」的讨论，这里可以直接检验。

**研究价值：**
- **大模型训练层面：** 可验证奖励 RL 是当前最热的方向之一，但它的奖励大多来自数学题和代码。临床方程提供了一个**有真实应用意义、奖励又完全可验证**的新场景。
- **部署层面：** 真实病历不能发给外部 API，**本地小模型是唯一合规的路径**，这让这个问题有直接的实用价值。
- 已有的 **MedCalc-R1** 的奖励里还用到冻结的 LLM 评委来检查公式；我们完全不用。

**怎么回答：**
- **训练数据：** 程序无限生成（NHANES 病人 + 渲染器 + 方程）。
- **训练：** Colab A100 / L4，用 TRL 或 Unsloth，LoRA + GRPO，模型 1.5B–3B 起步。
- **评测：** 同分布测试集；分布外测试集（真实病历、新方程、新的表述方式，即方向 ① 的改写）。
- **对照：** 只做 SFT / SFT + GRPO / 只给提示词 / 给工具。
- **分析：** 训练前后的错误类型分布（抽取、计算、弃权），以及可选的探针分析（内部风险值的可读性是否提高）。

**风险：**
- Colab 资源不稳定，T4 跑不动 GRPO，**至少需要 L4 或 A100**（Colab Pro）。7B 以上的模型成本明显上升。
- 可能出现「同分布大涨、分布外不动」。**但这本身就是回答研究问题 3 的结果。**
- 工程量最大，建议在 A 或 B 的测试台建好之后再做。

### RQ-D 算力该花在「多想」还是「调工具」？（推理算力与架构）

**研究问题：** 在临床计算类任务上，增加推理长度（OpenAI 的 reasoning effort、Qwen3 的 thinking 模式）和调用计算工具，各自带来多少提升？有没有「想多了反而把对的改错」？工具调用会引入哪些新错误（参数填错、单位错）？

**研究价值：** 这是大模型工程的实际选择问题。已有工作分别证明了「给工具能大幅减错」（npj DM 2025，错误减少 5.5–13 倍）和「想太多会变差」（2604.10739），但**没人在同一任务上把两者放在同一条成本-准确率曲线上比较**。

**怎么回答：** 同一测试集 × {不思考 / 低 / 中 / 高推理强度} × {不给工具 / 给工具}，记录准确率、token 数、延迟、金额，画出帕累托前沿。

**风险：** **单独撑一篇的新颖性偏弱**，更像工程评测。**建议作为 A、B、C 里的一个实验条件，而不是独立题目。**

---

### RQ-E 表述不同但信息相同时，模型稳定吗？（鲁棒性，即方向 ①）

**研究问题：** 同一病人用不同的写法、单位、语言、格式呈现，模型的决定会变吗？稳定性和模型规模、训练方式有什么关系？

**价值与现状：** 宽泛的结论已经被 8 篇以上的工作占了。我们的独特之处是「信息等价由程序保证」。先导数据显示，前沿模型在表面改写下几乎不变（翻转 2/120，与重复噪声持平）。

**建议：** **不单独成题**，作为 A、B、C 的泛化测试维度。比如 RQ-C 训练后的小模型在换了写法的病例上还稳不稳，这正是 RQ-C 研究问题 2 要回答的内容。

## 2. 比较与建议

| | 大模型问题类别 | 新颖性 | 标准答案 | 资源 | 起步速度 | 主要风险 |
|---|---|---|---|---|---|---|
| **A 知识冲突** | 上下文 vs 参数知识、知识更新 | **高**（病人层面、可计算的新旧冲突还没人做） | 两个方程 | API + Colab | **快**（NHANES 公开，只需补 PCE） | 前沿模型可能完全服从上下文 |
| **B 可判定性** | 选择性预测、校准、神经-符号 | **中高** | 区间运算 | API + 本地 | 快（脚本已有） | 与 SCORE2 那两篇相邻 |
| **C 可验证奖励 RL** | 后训练、泛化 | **中高** | 程序奖励 | Colab A100 / L4 | 慢（依赖 A 或 B 的测试台） | 算力；只学到格式 |
| D 推理算力 | 测试时算力、工具 | 中低 | 同上 | API | 快 | 单独不够 |
| E 鲁棒性 | 表述不变性 | 中低 | 等价性 | 已有 | 最快 | 可能零结果 |

**建议的博士主线：**

> **「大模型能否可靠地执行可计算的临床规则：规则更新时听谁的（A）、信息不全时知不知道该弃权（B）、能否通过可验证奖励把这些能力训练进本地小模型（C）」**

- **第一篇：A 或 B。** 两者都能在 NHANES 公开数据上用 API 快速做起来，并且共用同一个测试台：病人 × 方程 × 程序算出的标准答案。
- **第二篇：另一个。**
- **第三篇：C**，用前两篇积累的测试台训练本地小模型，并在真实 MIMIC 病历上检验泛化。
- D 和 E 作为各篇里的实验条件。原方向 ③（探针）作为 A 或 C 的机制分析。

**HTN-Concord 的哪些东西能直接用：** NHANES 管线、PREVENT（已验证）、渲染器、runner、确定性评分、MIMIC 管线。**不再需要：** 手写整套指南规则当金标准，以及 HC-49 医生裁定这个关键路径。

## 3. 必须提前确认的约束

1. **MIMIC 与外部 API：** PhysioNet 的数据使用协议限制把受控数据发给第三方在线服务。**MIMIC 上的实验默认只在本地跑 Qwen**；GPT 类模型只用在 NHANES 这类公开数据上。**Colab 算不算合规的计算环境，也需要按 PhysioNet 当前的负责任使用说明核对**，我没有逐条核实。
2. **PCE 的实现：** RQ-A 需要把 Goff 2013 PCE 按原文录入系数，并用原文算例验证。这是照原文抄写，不需要临床判断。
3. **与导师确认转向**，以及 HTN-Concord 进行中的工单（HC-49、HC-94 等）如何处理。

## 4. 每个题目的两周先导实验（用来决定做不做）

| 题目 | 先导内容 | 继续做的条件 |
|---|---|---|
| A | 实现 PCE → 在 NHANES 上找出与 PREVENT 结论不同的病例 → 300 个冲突病例 × 3 种给规则方式 × Qwen3-8B 与一个 GPT 模型 | 冲突病例足够多（>15%），且至少一个模型退回旧版率明显 >0（比如 >10%） |
| B | 300 个 NHANES 病例，隐去血脂 × τ = 7.5% × Qwen3-8B 与一个 GPT 模型，要求回答「一定高 / 一定低 / 无法判定」 | 至少一个模型的两类错误率之和明显高于神经-符号基线 |
| C | Colab 上用 Qwen2.5-1.5B 对 PREVENT 计算做 GRPO，跑 300 步 | 同分布准确率有提升，且训练稳定 |
