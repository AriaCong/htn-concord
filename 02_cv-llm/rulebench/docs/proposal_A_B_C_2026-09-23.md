# 研究方案：大模型能否可靠地执行可计算的临床规则（2026-09-23）

> **已被 v2 取代（2026-09-25）：** 现行方案见 `proposal_v2_2026-09-25.md`（诊断 → 修复 → 训练）。本文件保留作记录，说明最初的设计和改动原因。


三项研究共用一个测试台：**病人档案 × 已发表的风险方程 → 由程序算出的标准答案**。医学只是背景，研究对象是大模型本身。

- **A**：规则更新时，模型听上下文还是听记忆（知识冲突）
- **B**：信息不全时，模型知不知道能否下结论（可判定性 / 选择性作答）
- **C**：能否用程序给分的强化学习，把 A 和 B 的能力训练进本地小模型

文中所有「预期结果」都是**假设**，并且给出了每种结果各自说明什么。结果反过来也有发表价值。

## 0. 共用的测试台（先建，A、B、C 都用）

### 0.1 代码结构

新建仓库 `cv-rulebench/`，与 `htn-concord-main/` 平行。HTN-Concord 中已验证的模块直接复用，引用而不复制。

```
cv-rulebench/
  cohort/        NHANES 档案加载（复用 pipelines/nhanes）
  equations/     prevent.py（复用，已对原文算例验证）
                 pce.py（新写：Goff 2013 PCE，用原文算例验证）
  labels/        conflict.py        A：新旧两版各自的决定
                 determinability.py B：区间运算 → 一定高 / 一定低 / 无法判定
  render/        复用 HTN-Concord 渲染器；新增 A、B 的题面模板
  prompts/       每个条件一个版本化的提示文件，冻结后记录 SHA-256
  runners/       openai_runner.py（API，只用于公开数据）
                 hf_runner.py（Qwen，Colab 或本地，用 vLLM 批量推理）
                 所有调用以 JSONL 缓存：病例 id、条件、模型、种子、原始输出
  eval/          JSON 解析、指标、自助法置信区间、混合效应模型
  train/         C：SFT 与 GRPO 脚本（TRL）
  notebooks/     分析与作图
```

### 0.2 原则

- **标准答案只由程序产生。** 不用 LLM 评委，也不做人工标注。
- **提示词冻结后才跑正式实验。** 先导实验用单独的一份数据，正式数据只跑一次。
- **数据合规。** NHANES 是公开数据，可以发给 API；MIMIC 只在本地跑 Qwen。Colab 是否合规需要按 PhysioNet 当前的说明核对，**核对之前 MIMIC 不上 Colab**。
- 每个条件跑 k = 3 次采样，温度固定；报告重复之间的噪声作为基线。

## A. 规则更新时，模型听上下文还是听记忆

### A.1 背景

- **2017 ACC/AHA：** 1 期高血压（130–139/80–89），不合并临床心血管病、糖尿病、慢性肾病时，按 **PCE 10 年 ASCVD 风险 ≥10%** 决定是否用药。
- **2025 AHA/ACC：** 同类病人改按 **PREVENT 10 年总心血管病风险 ≥7.5%**。
- PCE 在当代人群中大约把风险高估一倍（MESA 等队列的研究结论）。所以同一个病人按两版可能得出相反的结论。
- 大多数模型的训练语料里，2017 版和 PCE 已经存在了八年，2025 版只有一年左右。

### A.2 研究问题

- **RQ-A1**：不给任何规则时，模型默认用哪一版？
- **RQ-A2**：明确给出 2025 规则后，在两版结论不同的病例上，模型有多大比例仍然按旧版决定？
- **RQ-A3**：新规则以什么形式提供，最能压住旧知识：一句指令、指南原文片段、从整份指南检索（RAG），还是计算工具？
- **RQ-A4**：模型会不会把新旧规则混用，比如用 PCE 的数值配 7.5% 的阈值？这种错误有多常见？
- **RQ-A5**：退回旧版的程度，和模型规模、推理模式有什么关系？
- **RQ-A6（进阶）**：在 Qwen 上做 LoRA 微调，能否消除退回旧版，同时不损害其他能力？

### A.3 研究价值

1. **对大模型研究：** 上下文与参数知识冲突的研究，大多针对**事实型知识**，比如「某国首都是哪里」。医学上的 TempoMed-Bench、DriftMedQA 也是选择题式的知识回忆。**「程序性、数值型规则」的冲突**（换了一个方程、换了一个阈值）研究很少。这里的每个结论都能精确算出，是一个干净的受控试验台。
2. **方法贡献：数值指纹。** PCE 和 PREVENT 对同一个病人给出的数值差别很大（大约两倍）。所以只看模型报出的风险数值，就能反推它**实际在用哪个方程**，哪怕它嘴上说自己用的是 PREVENT。这种方法可以推广到任何「新旧公式并存」的领域。
3. **对实践：** 指南每隔几年就会更新。已经部署的 LLM 如果悄悄沿用旧规则，没有人会察觉。「新阈值配旧方程」尤其危险：PCE 数值偏高，阈值又降低了，两者叠加会**系统性地扩大用药人群**。量化这个问题，本身就有实用价值。

### A.4 方法

**人群（按规则可以直接判定，不需要临床判断）：**
- NHANES 2017–18，年龄 40–79（PCE 与 PREVENT 适用范围的交集）；
- 血压处于 1 期，无临床心血管病、糖尿病、慢性肾病，未服降压药；
- 两个方程的输入都齐全。

**标准答案：**
- `new = PREVENT ≥ 7.5%`，`old = PCE ≥ 10%`；
- **冲突集：** new ≠ old；**一致集：** new = old，用来衡量基础能力。
- **注意：** PCE 需要种族（白人 / 非裔），PREVENT 不需要。实现时照原文处理，并在论文里说明。

**先要做的：** 实现 `pce.py`，用 Goff 2013 原文给出的算例逐位验证；然后统计冲突集占比。如果冲突集少于 15% 或少于 150 人，需要放宽人群，比如纳入 30–39 岁只看 PREVENT、或放宽血压范围，再重新评估。

**题面：** 用渲染器把病人档案写成病例描述。要求模型输出 JSON：

```json
{"risk_percent": 9.1, "equation": "PREVENT", "threshold_percent": 7.5, "decision": "start_medication"}
```

**实验条件：**

| 代号 | 给模型什么 | 测什么 |
|---|---|---|
| C0 | 只说「按现行指南」 | 默认记忆（RQ-A1） |
| C1 | 明确指令：用 2025 版，PREVENT ≥ 7.5% | 显式覆盖 |
| C2 | 贴 2025 指南相关段落原文，不做总结 | 隐式覆盖，模型要自己读出规则 |
| C3 | RAG：整份 2025 指南切块，检索前 5 段 | 贴近真实部署 |
| C4 | 给一个 `prevent_risk()` 工具 | 工具能否消除冲突 |
| C5 | 反向对照：明确要求用 2017 版 | 模型能不能「回到旧版」，也用来检验它是否真的会用 PCE |

**模型：**
- Qwen3 0.6B / 1.7B / 4B / 8B / 14B：Colab A100 用 vLLM 推理；32B 用 4-bit 量化或跳过；
- OpenAI API：2–3 个模型，推理型和非推理型各至少一个；
- 每个模型的训练截止时间写入附表。

**指标：**

| 指标 | 定义 |
|---|---|
| **退回旧版率（RR）** | 冲突集中，决定与旧版一致的比例 |
| 遵从率 | 冲突集中，决定与新版一致的比例 |
| **数值指纹** | 对每个输出算 d = \|log(报告值 / PREVENT)\| − \|log(报告值 / PCE)\|；d > 0 表示数值更接近 PCE |
| **混用率** | 报告阈值为 7.5%，但数值指纹指向 PCE 的比例 |
| 一致集准确率 | 基础能力，用来排除「只是不会算」的解释 |

**统计：** 混合效应逻辑回归，因变量是「是否退回旧版」；固定效应为条件、模型规模和两者的交互；病人作随机效应。条件两两比较用 McNemar 检验；置信区间用自助法。

**进阶（RQ-A6）：**
- 在 Qwen3-4B 或 8B 上，用程序生成的「按 2025 版正确作答」样本做 LoRA 微调，约 2,000 条；
- 测微调后的退回旧版率；
- 在 MedQA 子集和一个通用基准上测能力损失；
- 与 C1 / C4 比较：值不值得为此训练。

**可选的机制分析：** 在 Qwen 的隐藏层上训练线性探针，分别读 PCE 值和 PREVENT 值，看模型内部更接近哪一个。这就是原方向 ③ 的内容。

### A.5 预期结果（假设）

| 假设 | 预期 | 如果相反，说明什么 |
|---|---|---|
| H-A1 | C0 下多数模型默认按旧版，数值指纹偏 PCE | 模型已经吸收了新版。这本身是关于知识更新速度的发现 |
| H-A2 | C1 大幅降低退回旧版率，**但小模型仍明显 > 0** | 如果所有模型都 ≈ 0，冲突在显式指令下不成问题，结论落到 C2/C3 的隐式条件上 |
| H-A3 | **混用率 > 0**：嘴上说 PREVENT、7.5%，数值却是 PCE 的 | 如果混用率为 0，说明模型要么完全用新版、要么完全用旧版，这也是一个清楚的机制结论 |
| H-A4 | C2、C3 比 C1 差，而且上下文越长越差（新规则被长文本稀释） | 如果 C3 更好，说明检索到的原文比一句指令更有说服力 |
| H-A5 | C4 让退回旧版率接近 0，但会出现工具参数错误 | — |
| H-A6 | 退回旧版率随规模下降；推理模式不一定有帮助 | — |

**最可能的论文主结论：**「大模型在显式指令下大多能切换到新规则，但在隐式和检索条件下会部分退回旧规则；而且存在一种隐蔽的『新阈值配旧方程』混用，它会系统性地扩大用药人群。」**这需要实验验证。**

### A.6 工作量

| 阶段 | 内容 | 时间 |
|---|---|---|
| 1 | 实现并验证 PCE；统计冲突集大小 | 1 周 |
| 2 | 题面、提示、runner；先导实验（300 例 × C0/C1/C2 × 2 个模型） | 2 周 |
| 3 | 冻结提示；正式运行全部条件和模型 | 3–4 周 |
| 4 | 分析、LoRA 进阶、写作 | 6–8 周 |

**成本：** API 部分是几千到几万次调用；Qwen 部分是 Colab A100 上的批量推理，按小时计。精确金额要等先导实验跑完再估。

**止损条件：** 如果先导实验中所有模型在 C1、C2 下的退回旧版率都 < 3%，而且混用率也 < 3%，就把 A 缩成 B 的一个小节，主线转到 B。

## B. 信息不全时，模型知道自己能不能下结论吗

### B.1 研究问题

- **RQ-B1**：缺少部分输入时，LLM 能否正确区分「一定高于阈值 / 一定低于阈值 / 无法判定」？两类错误（过早下结论、过度弃权）各占多少？
- **RQ-B2**：错误率和「离阈值有多远」有什么关系？所谓离阈值多远，指风险区间到 τ 的距离。
- **RQ-B3**：哪种不确定性信号最能预测应当弃权：模型自报的置信度、多次采样的一致性、答案 token 的概率，还是隐藏状态探针？
- **RQ-B4**：神经-符号架构（LLM 只抽取并标出缺失，由区间求解器判定）能消除哪些错误？剩下的错误是什么？
- **RQ-B5**：面对真实病历时，模型会不会自己「编」出缺失的数值，比如填一个典型的胆固醇值？

### B.2 研究价值

1. **对大模型研究：** 选择性预测（什么时候不答）是可靠性研究的核心问题，但缺少**标准答案可以精确算出**的测试台。现有的「应当弃权」标注，要么靠人判断，要么靠删掉选择题的正确选项来人为构造。这里的可判定性由区间运算在数学上确定，而且可以按「离阈值的距离」连续地控制难度。
2. **可以连续控制难度**，这在其他弃权基准里很少见。
3. **对实践：** 临床决策支持最常见的真实情况，就是信息不全。系统应该说的是「需要先查血脂」，而不是编一个数字出来。

### B.3 方法

**病例生成：**
- 从 NHANES 中取 PREVENT 输入齐全的人（30–79 岁）；
- 按缺失模式隐去部分变量：{总胆固醇 + HDL}、{糖尿病状态}、{eGFR}、{总胆固醇 + HDL + 糖尿病}，以及不缺失的对照；
- 阈值 τ ∈ {5%, 7.5%, 10%, 20%}。

**标准答案：**
- 连续变量在 NHANES 第 1–99 百分位范围内取值，二值变量两种取值都试；
- 用网格加数值优化求出风险的最小值和最大值（PREVENT 不是处处单调，不能只取端点）；
- 最小值 ≥ τ → 一定高；最大值 < τ → 一定低；否则 → 无法判定。
- 代码已有：`cv-llm-risk-extraction/feasibility/03_determinability.py`。

**抽样：** 在三类答案之间，以及不同「区间到阈值距离」的区段之间做平衡抽样，比如 1,500 例。

**输出格式：**

```json
{"answer": "UNDETERMINED", "confidence": 70, "missing_needed": ["total_chol", "hdl"]}
```

**实验条件：**
- B-direct：直接回答；
- B-CoT：先推理再回答；
- B-formula：提供方程；
- B-tool：提供 `prevent_risk()`，让模型自己决定怎么在缺失情况下使用它；
- **B-NS（神经-符号）**：LLM 只输出抽取结果（缺失填 null），由我们的区间求解器判定。

**真实病历分支（只在本地跑 Qwen）：**
- 输入 MIMIC 出院小结 + 结构化的年龄、性别、SBP（取 OMR）；
- 血脂在小结里天然缺失（可行性检查显示 94% 缺）；
- 标准答案由结构化数据加区间运算得出。

**指标：**
- 三分类宏 F1；
- **过早下结论率**（应答「无法判定」却给了结论）；**过度弃权率**（可以判定却弃权）；判错方向率；
- 风险-覆盖率曲线与 AURC；各种不确定性信号预测「应当弃权」的 AUROC；
- **编造率**（仅真实病历分支）：模型给出的胆固醇数值在病历中并不存在的比例。

### B.4 预期结果（假设）

| 假设 | 预期 |
|---|---|
| H-B1 | 信息齐全时准确率高；缺失时，过早下结论与过度弃权同时存在（与 ClinDet-Bench 一致，但在连续方程上） |
| H-B2 | 错误集中在区间贴近阈值的病例上，错误率随距离单调下降 |
| H-B3 | 多次采样一致性和隐藏状态探针，比模型自报的置信度更能预测应当弃权 |
| H-B4 | 神经-符号架构几乎消除过早下结论；剩下的错误主要来自「没识别出缺失」 |
| H-B5 | 真实病历分支中存在非零的编造率，尤其是写了「高脂血症，服他汀」但没有数值的病历 |

**最可能的论文主结论：**「LLM 的弃权失败不是随机的，而是由到阈值的距离决定的；把判定交给符号求解器可以消除大部分错误，但真实病历里的缺失识别和数值编造仍是瓶颈。」

### B.5 工作量

- 标准答案代码已经基本完成，需要扩展到多种缺失模式：1 周；
- 先导实验：2 周；正式实验：4 周；
- 真实病历分支：3–4 周（本地 Qwen）；
- 分析与写作：6 周。

## C. 用程序给分的强化学习训练本地小模型

### C.1 研究问题

- **RQ-C1**：用可验证奖励（GRPO）训练的 1.5–4B Qwen，在 A 和 B 的任务上，能否接近 API 大模型？
- **RQ-C2**：学到的东西能否迁移？
  - 换一种写法（原方向 ① 的改写）；
  - 没见过的缺失模式；
  - 另一个方程（PCE，来自研究 A）；
  - 真实 MIMIC 病历。
- **RQ-C3**：提升来自真正的计算能力，还是只是格式更规整、失误更少？

### C.2 研究价值

1. **对大模型研究：** 可验证奖励强化学习的奖励大多来自数学题和代码。临床方程提供了一个奖励完全可验证、又有真实应用意义的场景。RQ-C3 可以直接回应「这类强化学习只让模型更快、不让模型更聪明」的争论。
2. **对部署：** 真实病历不能发给外部 API，本地小模型是唯一合规的路径。
3. 与 MedCalc-R1 的区别：它的奖励里还用了 LLM 评委，我们完全由程序给分。

### C.3 方法

- **基础模型：** Qwen2.5-1.5B-Instruct、Qwen3-1.7B / 4B。
- **热启动 SFT：** 约 2,000 条由程序模板生成的解题过程（不用 LLM 生成）。
- **GRPO：**
  - 用 TRL 的 GRPOTrainer，LoRA；Colab A100 40GB 或 L4；
  - 每组 8 个样本，最大长度 1,024，先跑 300 步做先导，再跑正式训练。
- **奖励：** 各部分加权相加，权重在先导阶段确定后冻结：
  - JSON 格式合法；
  - 决定正确；
  - 风险数值误差在 ±1 个百分点以内（软奖励）；
  - 可判定性正确；
  - 超长惩罚。
- **数据划分：** 按病人划分，训练病人与测试病人不重叠。
  - 同分布测试：新病人，同样的模板；
  - OOD-1：新写法；OOD-2：新缺失模式；OOD-3：PCE 任务；OOD-4：MIMIC 病历（本地）。
- **对照：** 未训练的基础模型；仅 SFT；SFT + GRPO；基础模型 + 工具；API 大模型。
- **区分「能力」还是「格式」：**
  1. 训练前后的错误类型分布（抽取 / 计算 / 弃权）；
  2. 只换输出格式（JSON 换成自然语言）后，提升是否保留；
  3. 可选：探针看内部的风险值读出精度是否提高。

### C.4 预期结果（假设）

| 假设 | 预期 |
|---|---|
| H-C1 | 同分布大幅提升，其中很大一部分来自格式错误和算术失误的减少 |
| H-C2 | OOD 提升明显小于同分布；真实病历上的提升最小 |
| H-C3 | **「基础小模型 + 工具」可能接近 GRPO 的效果。** 如果成立，结论是「训练不如给工具」，这对部署同样有价值 |
| H-C4 | 只换输出格式后，部分提升消失，说明其中有一部分只是学到了格式 |

### C.5 工作量与风险

- 4–6 个月，必须在 A 或 B 的测试台建好之后开始；
- Colab 的算力不稳定，T4 跑不动，需要 Colab Pro 的 A100 或 L4；
- **止损条件：** 300 步先导内同分布没有提升或训练不稳定，就改成只做 SFT 对比，或者把 C 并入 A 的 RQ-A6。
