总结论

实验 1MIMIC 病历可行性检查

原来的设想是让模型从出院小结里读出风险公式需要的数值，再算风险。这个实验先检查：小结里到底有没有这些数值，能不能拿结构化表当标准答案。

1.1

抽 50 份出院小结

代码
exp1_mimic_feasibility/01_sample.py
输入
HTN-Concord 已建好的 MIMIC 队列（30–79 岁、有入院当次出院小结，共 5,358 份）
输出
out/sample_notes.csv

怎么做

用固定随机种子 20260923 抽 50 份：结构化数据「能算出 PREVENT」的 25 份，「算不出」的 25 份。分两组抽，是为了两种情况都覆盖到。

1.2

从 MIMIC 大表里筛出这 50 人的记录

代码
exp1_mimic_feasibility/01b_extract_subset.sh（当时是终端命令，已按会话记录还原成脚本）
输入
MIMIC-IV 3.1 的化验、门诊、入院表；MIMIC-IV-ED 2.2 的急诊表
输出
这 50 人的化验、门诊记录、入院记录、急诊分诊和生命体征

怎么做

边解压边按病人编号过滤。化验只保留 9 项：肌酐、血钾、血糖、HbA1c、总胆固醇、HDL、LDL（两种）、甘油三酯。

1.3

小结里写的数值 vs 结构化表

代码
exp1_mimic_feasibility/02_compare.py
输入
1.1 和 1.2 的输出
输出
value_matches.csv、bp_matches.csv、coverage.csv

怎么做

  • 化验模板行（例如 06:30AM BLOOD Creat-0.9）带时间，按「项目 + 时间 + 数值」去化验表里找。
  • 正文里零散的数值（例如「Cr 1.4」）没有时间，只能在入院前一年内按数值找。为了看是不是巧合，同时检查「数值挪一步」是否也能对上。
  • 覆盖率：每个变量在小结里写了没有，表格里有没有。
  • 血压：小结里的血压和急诊读数、入院前最后一次门诊血压比较。

结果

检查项结果
化验模板行与化验表完全对上275 / 282（97.5%）
正文数值「挪一步也能对上」的比例（肌酐 / 血钾）41% / 53%
小结里写了总胆固醇 / HDL3 / 50、2 / 50
化验表里入院前一年有总胆固醇 / HDL34 / 50、33 / 50
小结血压与门诊血压的差（中位数）12 mmHg；32% 差 ≥ 20
结论：化验模板行可以当标准答案，但正文里零散的数值不行，按数值匹配大多是巧合。血脂几乎不写在出院小结里，光凭小结 94% 的人算不出 PREVENT。小结里的血压是住院时测的，和公式要求的平时血压不是一回事。
1.4

缺血脂时，结论还能定下来吗

代码
exp1_mimic_feasibility/03_determinability.py（独立运行）
输入
全队列中能算出 PREVENT 的 2,376 人；NHANES（只用来定血脂的合理范围）
输出
各阈值下「可判定」的比例（屏幕打印）

怎么做

假装不知道总胆固醇和 HDL，让它们在常见范围内变动（总胆固醇 107–300、HDL 28–97 mg/dL，即 NHANES 人群的第 1–99 百分位），在 15×15 的网格上算出风险的最小值和最大值。整个范围都在阈值同一侧，就是「可判定」；跨过阈值，就是「无法判定」。这个方法后来也用在实验 2 的 B 部分。

结果

阈值可判定无法判定
5%71.3%28.7%
7.5%61.8%38.2%
10%56.7%43.3%
15%51.3%48.7%
20%51.6%48.4%

重算的 PREVENT 和原先存的值完全一致；98.4% 病人的真实风险落在算出的范围内。

结论：在 7.5% 阈值下，大约六成可判定、四成不可判定，比例适合做评测：模型既不能一律作答，也不能一律说「无法判断」。

实验 1 总结论

  • 「从出院小结里读数值再算风险」这个原设计做不成：关键的血脂数据不在小结里。
  • 「给出部分信息，判断结论能不能定下来」这个设计完全可行，标准答案可以全部由程序算出。这就是后来的研究 B。
  • MIMIC 只能在本机处理，不能发给任何外部 API。

实验 2先导实验 A + B

用公开的 NHANES 数据生成病例，让模型按规则给出开不开药的决定，和程序算出的标准答案比对。流程分四步：准备 → 生成病例 → 出题并调用模型 → 打分；调用模型这一步跑了 5 轮。

NHANES + 病史问卷 ─build_cases.py（调用 pce + prevent）─▶ cases.jsonl（140 个病例 + 标准答案）
cases.jsonl ─run_pilot.py（本机 Ollama / OpenAI）─▶ calls.jsonl（每次调用的原始回答）
calls.jsonl ─analyze.py─▶ scored.csv（逐条得分） + report.txt（汇总表）
2.0

准备：补数据、写旧公式

代码
shared/pce.py；下载命令见 exp2_pilot_A_B/run_commands.sh 第 0 段
输出
pilot/data/MCQ_J.xpt
  • 补心血管病史：HTN-Concord 的 NHANES 档案里「有无心血管病」一列全是空的，所以从 CDC 下载公开的病史问卷 MCQ_J，用心衰、冠心病、心绞痛、心梗、卒中五项补上。
  • 写 PCE 公式：按 Goff 2013 原文的系数表录入，用原文的算例核对：4 组结果都对上（误差 ≤ 0.1 个百分点）。白人男性精确计算得 5.38%，原文印的是 5.3%，原因是原文先把每一项取整再求和。
  • 发现并修正了一个错误：PREVENT 代码返回的本来就是百分数，第一次生成病例时误以为是小数，又乘了 100。修正后删掉当时的结果，从头重跑。
待办：正式实验前，PCE 的系数需要另一个人对照原文再核一遍。
2.1

生成病例和标准答案

代码
exp2_pilot_A_B/build_cases.py
输入
NHANES 2017–18 档案（4,806 人）+ MCQ_J 问卷
输出
cases.jsonl（A 80 例 + B 60 例），pilot_seqns.txt（正式实验要排除这些人）

A 部分怎么做

筛出 40–79 岁、1 期高血压、没有心血管病 / 糖尿病 / 慢性肾病、没吃降压药的人，用两个公式各算一遍。

项目结果
符合条件244 人
新旧规则结论相反（冲突病人）14 人（5.7%）
其中：旧规则开药、新规则不开 / 反过来9 / 5
两个公式算出的风险之比（中位数）1.11 倍

14 个冲突病人太少，所以在真人数据上随机改动年龄、血脂、血压（仍在 1 期范围）、吸烟，补了 36 个合成冲突病例，凑满 50 个；另抽 30 个一致病人。

B 部分怎么做

从另一批 30–79 岁的人里随机抽 900 人，隐去血脂，用实验 1 的区间方法判定答案。结果：一定不开 405、无法判断 265、一定开 230。三类各抽 20 人，共 60 例。

结论：原方案假设旧公式大约比新公式高一倍、冲突病人至少占 15%，两条都不成立。原因之一是 PREVENT 把心衰也算进去了，两个公式的差距因此缩小。
2.2

出题、调用模型

代码
exp2_pilot_A_B/run_pilot.py；每轮的实际命令见 run_commands.sh
输出
calls.jsonl：每次调用的题目、原始回答、思考 / 推理摘要、token 数、费用

怎么做

把每个病例写成一段英文病例描述，要求模型只输出 JSON。每个病例有 6 种问法：

代号给模型什么测什么
C0_current只说「按现行美国指南」不给规则时，模型默认用哪版
C1_new_rule明确写出 2025 新规则给了新规则，会不会照做
C5_old_rule明确写出 2017 旧规则反向对照：会不会用旧规则
C1_plus_risk新规则 + 直接告诉它算好的 PREVENT 值去掉「算」这一步后还会不会错
B_direct新规则 + 藏起血脂的病例能否判断结论定没定
B_plus_range再告诉它风险可能落在哪个范围去掉「算范围」这一步后还会不会错

A 部分要求输出：风险值、自称用的公式、阈值、决定。B 部分要求输出：一定开 / 一定不开 / 无法判断、置信度、还需要哪些数据。本地 Qwen 温度设为 0、固定随机种子；每个病例只问一次。

2.3

打分

代码
exp2_pilot_A_B/analyze.py
输出
scored.csv、report.txt

全部由程序完成：解析模型输出的 JSON，和标准答案比较。主要指标：

  • 正确率：决定是否符合题目要求的规则，冲突病人和一致病人分开算。
  • 风险值准不准：报出的风险和真实 PREVENT 的相关系数、误差中位数。
  • 自称用的公式：归为 PREVENT / PCE 一类 / 其他。
  • 自洽性：决定和它自己报的风险值、阈值是否一致。
  • 错误分类：阈值错 / 风险值错 / 决定与自己的数字矛盾。
  • B 部分：过早下结论（本该「无法判断」却给了结论）、过度弃权（本可判断却说「无法判断」）、方向判反。
  • 推理文本：用关键词粗筛「笔误」「占位符」和旧公式名，命中的逐条人工阅读。

  • 静默替换只是偶发：病例 102789 第 1 次报 8.5%（正好是 PCE 的 8.47%），后两次都报 6.4%（正好是 PREVENT 的 6.42%）。
  • 新发现：错误地声称缺输入。PREVENT 的总心血管病方程里没有 BMI，BMI 只用在心衰方程里。模型可能记住的是官方在线计算器的界面（那里要求填 BMI），而不是方程本身。这和研究 B 的「过度弃权」是同一类失败：以为缺了必要的输入，其实不缺。
  • 这一轮还修正了一个打分问题：模型不给决定时，原来被算成「不开药」，现在单独记为「拒绝作答」。只影响本轮 astra 的数字。
结论：最强的模型基本不「退回旧版」。它剩下的问题是另一种：以为缺了其实不需要的输入。

实验 2 总结论

失败类型出现在什么能修好
算不准风险所有模型给数值 / 计算工具 已验证
决定和自己的数字矛盾1.7B给数值也修不好 待研究
接受新阈值，却用旧公式8B、8B 思考、14B待测
把新规则当笔误8B 思考在 gpt-6-sol 上消失
拿旧公式当参照（较弱）gpt-6-sol换更强的模型后消失；需要更好的对照才能测准
静默替换：自称用新公式，报的却是旧公式的值gpt-6-astra，约 1%偶发，重复采样没有再出现
以为缺了其实不需要的输入（BMI）gpt-6-astra，4.7%待测：提示里写明方程需要哪些输入
本可判断却说「无法判断」8B、14B给范围后大部分修好，14B 仍有残留

一句话：「退回旧版」随模型变强而减弱，不能单独撑起一篇论文。不同规模卡在不同环节，同一种修法（给数值）只修得好一部分，这正是建议方案要研究的问题。

对方案选择的含义

原方案：A / B / C 三篇各自独立建议方案：诊断 → 修复 → 训练
论文 1A：新旧规则冲突时听谁的诊断：把 A、B 合并，逐环节定位错误
论文 2B：信息不全时能否判断修复：从便宜到昂贵试各种办法，看哪种修好哪类错
论文 3C：强化学习训练小模型训练：强化学习，和最好的修法比
前提A 的效应要大到能单独成篇错误能分成几类，修法各不相同
先导实验前提不成立 冲突人群只有 5.7%；最强的模型会算，也不退回旧版前提得到支持 至少八类失败，不同规模主导的失败不同

建议选「诊断 → 修复 → 训练」。「新旧规则冲突」保留为诊断里的一个维度。这个转向最好和导师确认。

局限

  • 实验 1 只有 50 份小结，比例的置信区间很宽；正则规则比较粗；队列只选了入院前有门诊血压的人。
  • 实验 2 每个病例只问一次，只用了一种问法；50 个冲突病人里 36 个是合成的。
  • 前沿模型只测了研究 A；研究 B 的结论只来自 Qwen。两次余额用完：astra 只跑了 66/80 例，重复采样只在 42 例上齐全，所以 4.7% 和 1% 的置信区间很宽。
  • OpenAI 只提供推理摘要，看不到原始思考过程；astra 约六成的摘要是空的。
  • 心血管病史来自问卷自报；PCE 系数需要第二人核对。

留给正式实验

先导实验已定稿，不再追加调用。以下几项放进正式实验的设计，前四项是必须做的：

  1. 把规则选择和计算分开：同时给出 PCE 和 PREVENT 两个数值。
  2. 贴近阈值的对照：一致组补充离 7.5% 不到 1.5 个百分点的病例。
  3. 「缺输入」检测项：检测模型是否声称缺了其实不需要的输入（A、B 共用）。
  4. 重复采样和多种问法：每例至少采样 3 次，至少两种提示写法；前沿模型用 Batch API（半价）。实测单价：astra 每次约 $0.062，sol 约 $0.02。
  5. 在前沿模型上测研究 B；14B 思考模式；PCE 系数第二人核对。
  6. 实验 1 的后续：糖尿病、吸烟、降压药、他汀四项与 HTN-Concord 银标对照。
  7. 确定方案后，改写方案文档和网页，补修复手段的文献。
