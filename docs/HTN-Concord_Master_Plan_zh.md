## 0. 约束每个阶段的原则（不得违反）

1. **无临床医生的确定性金标准。** 标签来自引擎，绝不来自 LLM 裁判。引擎无法判定的病例 → `ABSTAIN` + `not_encoded`，绝不猜测。
2. **Aria 手写指南规则；Claude 只搭周边脚手架**（pipeline、schema、渲染器、runner、评估器、基础设施）。这保住「医学逻辑是我写的」这一可辩护性。
3. **唯一的 `PatientProfile` schema。** 每个数据集都归一到它；下游代码永不按数据源分支。
4. **防泄漏纪律。** 清洗后的结构化行是**隐藏标签**。LLM 只会看到渲染出的病例文本（Task B）或原始病历（Task C）。标签列与任何喂给模型的文本**物理隔离**。
5. **可复现。** 确定性 pipeline、锁定版本、输入校验和、每个数据集一份 QA 报告、绝不手工改数据。
6. **各指南编码为独立模块**（AHA/ACC 2025 为主，ESC 2024 为对照）。分歧只**报告**，绝不合并。

### 2.2 MIMIC-IV 3.1（+ Note 2.2）—— 主要真实 EHR ⬜

**设计不变量（要写进论文）：** HTN 的 ICD 编码只用来识别*病人/就诊*（锚点）；慢性血压分期独立地由**该次就诊之前**的门诊 OMR 推导。**ICD 选病人，绝不生成标签。**

- **数据表：** `hosp/omr`（门诊血压字符串 `"120/80"` → 需解析；有体位变体）、`hosp/labevents`（按 itemid 过滤加载：肌酐 = 50912、钾 = 50971；用 `valuenum`，该表 2.4 GB）、`hosp/diagnoses_icd`（ICD-9/10 交叉映射）、`hosp/patients`（`dod`，年龄顶码 91）、`hosp/admissions`（`hospital_expire_flag`）、`note/discharge`（Task C 文本）。
- **锚点码集：** 纳入 ICD-9 `4010/4011/4019`（+`402–404` 仅作锚点）/ ICD-10 `I10`、`I11–I13`；**排除** ICD-9 `405` / ICD-10 `I15`（继发性高血压，出范围）。

- **2.2a — 先做可行性/衰减门（只计数，不建模）。** 在锁定队列之前先跑产出量查询：每条规则下还剩多少受试者（锚点就诊 → 365 天内 ≥2 个不同日期的既往 OMR 读数）。很多病人在 MIMIC 里的**首次出现就是**那次高血压就诊，因而没有既往 OMR 而掉队 —— 要报告**衰减瀑布图**。若 N 太小，则采用预注册的回退方案（730 天 / ≥1 次读数）作为主口径，把 365 天/≥2 留作敏感性分析。*这道门决定下面的规则，不可跳过。*

- **队列规则（v1，防泄漏）：** index = **最早**一次有合格既往 OMR 的锚点就诊（降低治疗演化偏倚）；OMR 是**唯一**的慢性血压来源；OMR 必须在 index 入院时间**之前**且在 365 天内；要求**≥2 个不同日期的读数**，取**中位数** SBP/DBP；现用药 = **入院前家庭用药**（`ed/medrecon` / 入院用药重整），**绝不用出院带药**（那会泄漏决策）；合并症/禁忌由 `diagnoses_icd` + `labevents` 推导（时间限定在 admittime 之前），**不从锚点码假设**；ED/住院血压只用于高血压急症附加场景，绝不用于慢性分期。

- **⚠️ 关键（2026-07-18 发现）—— 真正可决策的队列 N 约为 8,921，而不是 28,530。** 可行性门只统计了通过*血压*规则的病人。但计划同时规定现用药必须来自入院前家庭用药（`ed/medrecon`），绝不用出院带药 —— 而 **28,530 名 PRIMARY 受试者中只有 8,921 人（31.3%）在其 index 就诊有急诊用药重整**。`on_bp_meds` 正是区分*启动*与*强化*的那个变量；没有它引擎只能弃权。也就是说，头条队列里有三分之二拿不到主决策标签。
  **建议解决方案：** 把 index 就诊重新定义为「**最早的、既有 ED 关联、又有 365 天内 ≥2 个不同日期既往 OMR 读数**的锚点住院」—— 得到一个诚实的约 8,921 人队列，对基准而言仍然充足。把 28,530 保留为单独报告的**分期/Task-C** 队列。**不要**用出院带药去缓解 N 的压力。`hosp/prescriptions` 回退方案仅在限定为 `admittime` 后 24 小时内开立的医嘱、且预注册为敏感性分析时才可接受。

- **产出三个子队列：** **Primary**（锚点 + 合格既往 OMR → 主 Task-B 真实 EHR 一致性）；**OMR-only**（不论有无 HTN ICD 的合格 OMR → 捕捉未诊断/治疗不足者，价值最高的一致性缺口）；**Text-robustness**（锚点病人的出院小结，不要求 OMR → Task C 抽取与误差传播）。

- **步骤：** 可行性门 → 队列选择（最早锚点）→ OMR 血压解析器（带慢性/急性 **context flag**）→ 按 itemid 过滤的化验 → ICD→合并症/禁忌交叉映射 → 入院前用药重整 → 出院小结选择 → 派生共享字段 → schema 校验 → QA 报告。

- **验收门槛：** 衰减瀑布图已报告；三个子队列全部产出；档案通过 `patient_profile.schema.json` 校验；Task C 的银标准规范已定义；每一行血压/用药都执行了 context flag 与 index 前的防泄漏规则。

## 阶段 4 — 任务构建（病例 + 输入 + 标签）⬜

**目标：** 把带标签的档案转成四个任务数据集，并强制执行防泄漏规则。

- **Task A —— 结构化对照。** 干净的 `PatientProfile` 输入 → 引擎标签。属于下界，非主打。
- **Task B —— 叙事病例（主打）。** 渲染器把档案转成只暴露*原始事实*的散文（不含类别名、不含决策动词、不含「……的禁忌症」）。配一套手写、经一次性验证的干扰项库（例如「因血管神经性水肿停用了赖诺普利」[触发 flag] 对比「她父亲曾服用赖诺普利」[绝不能进入档案]）。三档难度。标签 = 引擎对隐藏行的判定。
- **Task C —— 真实文本鲁棒性。** 输入 MIMIC `note/discharge`；抽取高血压事实；用来自 `diagnoses_icd`+`labevents`+`medrecon` 的**银标准**评分；抽取出的事实再喂回引擎以测量误差传播。ICU 血压 → 弃权；慢性血压来自 `omr`。
- **Task D —— 外部合理性。** 把一致性与 NHANES 关联死亡率 / MIMIC `dod` 做关联。**只谈合理性，绝不谈疗效**（存在适应证混杂）。

**交付物：** 渲染器、干扰项库、难度控制器、任务数据集构建器、带校验和的冻结基准划分。
**验收门槛：** 泄漏审计通过（任何 Task B/C 输入中都不含带标签的 token）；人工抽查 20 份渲染病例确认「只含事实」。

## 阶段 5 — 模型 harness（LLM runner）⬜

**目标：** 以严格 JSON 模式、可复现地，让任意模型跑任意任务。

- JSON 模式 runner，输出符合 `llm_output.schema.json`（结构化字段使推理链评分成为可能）。
- 模型适配器：≥1 个前沿模型 + ≥1 个开源权重模型（用于 kill-criteria 对比）；vanilla LLM、朴素 RAG、指南图三种条件（RQ3）。
- Prompt 模板版本化；temperature/seed 锁定；完整请求/响应日志；成本与延迟记录；重试与缓存。
**验收门槛：** 确定性重跑能复现存档的 transcript；在冒烟集上畸形 JSON 率接近零。

## 阶段 6 — 评估与失败模式审计 ⬜

**目标：** 重点是**分解**，不是单一分数。实现全部计划指标与 RQ2 审计。

- **指标：** `decision_concordance`、`staging_correct`、`extraction_f1`、`contraindication_recall`、`contraindication_false_positive`、**`unsafe_recommendation`**（安全头条）、`citation_support`、**`trace_concordance`**、`abstention_appropriateness`。**按难度档**与**按亚组**（性别、年龄段、合并症）分别报告。
- **失败模式分类器（RQ2）：** 把每个失误标注为 血压分期错分 · 漏合并症 · 漏禁忌 · 用错药物类 · 忽略现用药 · 启动 vs 强化判错 · 不支持/造假的引用 · 答对但推理路径错 · 过度/不足弃权。每一类再标注为 抽取 / 推理 / 引用。
- **验收门槛：** 评估器在一个小型 gold set 上复现人工评分结果；2 模型 × 3 难度的报告能端到端渲染出来。
